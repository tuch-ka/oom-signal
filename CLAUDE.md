# CLAUDE.md

## Проект

oom-signal — Go-демон, мониторящий потребление памяти контейнера через cgroup и отправляющий сигнал процессу при превышении порога. Приложение само запускает oom-signal как фоновый процесс. Постановка задачи — в `task.md`.

## Стек

- Go 1.26, только стандартная библиотека, без внешних зависимостей
- Сборка: `make build` → `bin/oom-signal`

## Архитектура

- `src/cmd/main.go` — точка входа, парсинг флагов (`--threshold`, `--poll-interval`, `--pid`, `--signal`), запуск монитора, обработка SIGTERM/SIGINT для остановки
- `src/internal/monitor/monitor.go` — мониторинг с тикером через MemoryReader, отправка сигнала по rising edge
- `src/internal/memory_reader/memory_reader.go` — интерфейс `MemoryReader`, фабрика `NewMemoryReader()`, тип `MemoryReaderVersion`, общие хелперы
- `src/internal/memory_reader/cgroup_v1.go` — реализация `MemoryReader` для cgroup v1 (приватный тип cgroupV1)
- `src/internal/memory_reader/cgroup_v2.go` — реализация `MemoryReader` для cgroup v2 (приватный тип cgroupV2)
- `src/internal/signal/signal.go` — парсинг сигнала (signal.Parse/Name): имя или номер, номер без валидации
- `src/internal/threshold/threshold.go` — тип Threshold: два режима (процент 0.0–1.0 или запас в МБ), парсинг флага, метод Exceeded

## Ключевые решения

- oom-signal — демон, не супервизор. Не управляет жизненным циклом приложения, не пересылает сигналы, не делает graceful timeout/SIGKILL
- Безлимитный контейнер: v2 limit="max" или v1 limit>=2^62 — oom-signal завершается с exit 1, мониторить нечего
- Сигнал отправляется по rising edge: один раз при первом превышении, затем снова только после того как память опустится ниже порога и превысит его снова
- Приложение само обрабатывает полученный сигнал — это не зона ответственности oom-signal
- Реализации cgroup v1/v2 разделены по файлам, объединены через интерфейс MemoryReader — позволяет поддерживать версии независимо и в будущем добавить реализации без cgroup
